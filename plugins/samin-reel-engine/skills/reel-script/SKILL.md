# Reel scripting

Resolve `<plugin>` as the directory containing this plugin's `.codex-plugin/`. Run `python3 <plugin>/scripts/reel.py context` to find the configured project; pass `--project /absolute/checkout` **before** `context` when a project was supplied. Treat every `production/...`, `voice/...` and `runs/...` path as relative to that project. Shared references are linked below; load only this stage's instructions. Keep credentials and large working media out of the plugin cache.

Read [voice guide](../../references/voice-guide.md), [templates](../../references/templates.md), [shot recipes](../../references/shot-recipes.md), and the Scripting/check sections of [pipeline operations](../../references/pipeline-operations.md). Read three relevant original samples from the configured project; do not treat their factual claims as fresh evidence.

Write clean spoken copy separately from editor notes. Prefer concrete input → mechanism → payoff → useful CTA. Standard samples are generally 98–195 words; use the closest relevant sample and requested format rather than forcing a quota. Council's rapid delivery is a specific filmed example, not a universal speaking-speed assumption.

For each beat, attach the viewer question, visual job, source/asset request, important spoken noun/action and required readable detail. Do not claim a tested result when only documentation exists. Keep personal-use claims, numbers, free access and novelty grounded in evidence.

Build the promised resource or hand its exact specification to `reel-deliver`. Run the real script checker and Hold Your Voice scanner in the project. Inspect flags against the source samples; generic one-sentence-paragraph warnings are not reasons to destroy Samin's cadence. Save source/voice anchors and justified decisions.

Deliver a filming document plus individual clean scripts, word count, estimated duration, shot queue and matching CTA resources. Estimates become actual timing only after recording. Use Roughdraft when the user requests Markdown review, following the active workspace instructions.
